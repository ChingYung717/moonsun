## 2. 首批：状态边界、计算正确性和安全入口

### MS-01 · P1 · 统一时间范围与异常恢复

**原始证据**：`src/time/Clock.ts` 的推进和步进均无范围限制；`src/state/AppState.ts` 同时存在 `setTimeUtc` 与通用 `update` 写入入口；`src/main.ts` 在计算前安排下一帧。只给 `setTimeUtc` 加限制无法覆盖步进、恢复快照及直接 update。

**改动范围与方案**：

1. 在状态层统一定义支持区间（天文年 -1999 至 3000），构造、`update`、`setTimeUtc`、撤销和 URL 恢复均执行同一约束。拒绝 NaN/Infinity；明确非法输入保留原值，有限越界输入钳制到边界。
2. 到达边界时停止加速播放并退出实时同步，保留可恢复的有效时间；使用一次性提示，避免每帧通知。用日历年份构造日期，避免 JS 对 0–99 年的特殊处理。
3. 计算函数在区间边缘可能搜索前后若干天。验证依赖在边界附近的行为；必要时保护搜索窗口，不能只保证传入 Date 有效。
4. 为动画回调增加可恢复错误边界：暂停模拟、保留最后有效画面、抑制重复日志，并提供“回到现在”。不以空 catch 后逐帧重试代替恢复。

**验收**：覆盖上下界、0 年、非有限值、最大倍速、前后步进、URL/撤销写入；注入一次计算异常后播放停止、提示只出现一次、回到现在可恢复。不得依赖连续运行 39 天；用状态注入和时钟控制复现。新增状态/时钟测试，浏览器验证 UI 恢复。

### MS-02 · P1 · 下月点坐标修正

**原始证据**：`src/astro/eclipses/search.ts` 的 `computeSubLunarLatLon` 以 `Equator(... Observer(0,0,0) ...)` 的固定地表观测点坐标推导地理位置。

**实施**：使用地心月球向量，统一岁差章动、日期坐标系和恒星时，再转换经纬度。明确输出是地心方向对应的地理位置，还是严格的地表天顶位置；考虑椭球上地心纬度与大地纬度的区别。不要只用“地心”文案掩盖仍不准确的天顶承诺。

**验收**：多日期、多经纬度独立反算，处理赤经跨 0h、经度跨 ±180°。地心定义用独立向量算法交叉核对；若 UI 承诺天顶，则以该地表点的站心高度角接近 90°验收，并预先写明容差。评估 catalog 生成依赖，仅重建受影响数据并解释差异；回归中国可见性和带食日出/日落改动。

## 3. 第二批：性能与资源边界

### MS-06 · P2 · 月相搜索缓存与计算调度

`src/astro/phase.ts` 每帧重复搜索本朔望月的关键时刻。将“当前角度/照明比例”等轻量即时值与“朔、弦、望的时刻”分开；后者按模拟时间所属朔望月缓存，跨月、倒放、跳转时失效。缓存不得按现实分钟固定有效，最大倍速下会严重过期。

直接调用真实 `computeMoonPhase` 做预热后的对比基准，分别记录普通播放、暂停、最大倍速、倒放、跨朔时刻的结果；先保正确性，再比较同环境中位数/P95及搜索次数，不沿用“0.29ms、42倍、全帧最大项”等未经完整对照支持的结论。

`src/render/Renderer.ts` 的观测者天空计算仍被 `src/ui/InfoHUD.ts` 等消费。先梳理消费者，再降低不必要的更新频率；空间视角下的地面观测摘要仍须正确，不能仅按 viewMode 跳过计算。

### MS-07 · P2 · 阴影路径缓存有界化

为 `src/astro/eclipses/shadowPath.ts` 的 `pathCache` 加 LRU/容量策略，先测实际条目和内存占用再确定默认预算。缓存键保留当前计算精度含义，淘汰不影响结果。验收连续访问超出容量的事件后条目数有界、旧项可重新计算、重复访问结果一致。
